# Firebase data model

> Detailed entry from the 2026-09-10 system survey. The map that ties these together is [SYSTEM-OVERVIEW.md](../../SYSTEM-OVERVIEW.md). Status, evidence, and line numbers reflect the code and the live Firebase contents on that date; PRD `Status:` fields were deliberately not used as evidence.

**Database:** `https://gymnastics-graphics-default-rtdb.firebaseio.com` (project `gymnastics-graphics`), Realtime Database. It is the only shared bus between the Coordinator server, the SPA, and the OBS browser-source renderers. There is no Firestore usage and no Storage usage (media is external URLs on `media.virti.us`).

## 5. Access shape notes

**Client SDK (browser, modular v9 `firebase/database`).** The SPA's single Firebase entry point is `show-controller/src/lib/firebase.js` (21 lines). It hard-codes the full `firebaseConfig` (project `gymnastics-graphics`, `databaseURL` `https://gymnastics-graphics-default-rtdb.firebaseio.com`) and re-exports `db, ref, set, get, update, remove, onValue, push, onDisconnect` plus the Auth helpers. Every SPA hook, page and component imports from that module — there is no second `initializeApp` in `show-controller/src`. Two files use a bare root ref for atomic multi-path writes: `show-controller/src/hooks/useTeamsDatabase.js:218` (`saveHeadshots`) and `:320` (`reorderSponsors`). `show-controller/src/lib/themeResolver.js:114` is the only file that names its import `firebaseDb`.

**Client SDK (renderers, compat v9.22.0 loaded from gstatic).** The three renderer surfaces each initialize Firebase independently, with the same hard-coded config duplicated three times:
- `output.html` — script tags at lines 6639-6640, config at 7504-7513, `firebase.initializeApp` at 7513. Reads `competitions/{compId}/currentGraphic`, `production/engineHeartbeat`, `teamsDatabase/headshots`, `teamsDatabase/teams`, `themes/{themeId}`; writes `competitions/{compId}/production/clipStatus/{draftId}`.
- `overlays/theme-loader.js` — config at 192-195, and it **lazy-loads the compat SDK itself** (lines 215-228) if `firebase` is not already on `window`, so overlays that don't ship script tags still get a database. Reads `competitions/{compId}/config/meetTheme` and `themes/{themeId}`; writes `competitions/{compId}/production/themeErrors`.
- `stage/stage.html` — script tags 10-11, config 41-49. Reads `competitions/{comp}/currentGraphic`, `competitions/{comp}/config`, `themes/{themeId}`; writes `competitions/{comp}/production/stageErrors/{ts}`.

Only two other overlays touch Firebase at all: `overlays/team-bug.html` (its own compat init, plus a `.info/connected` subscription at line 831) and `overlays/rotation-slate-auto.html` (one `competitions/{compId}/config` read at line 1173). All other overlays — including every sponsor overlay, `who-to-watch*.html`, `rotation-slate.html`, the `frame-*.html` family — are driven entirely by URL query params generated by `show-controller/src/lib/urlBuilder.js` / `UrlGeneratorPage.jsx`. Nothing under `stage/blocks/` or `stage/graphics/` touches Firebase.

**Admin SDK (server).** Initialized exactly once, in `server/lib/productionConfigService.js:34-60`, using `admin.credential.applicationDefault()` (so `GOOGLE_APPLICATION_CREDENTIALS`) and `process.env.FIREBASE_DATABASE_URL` defaulting to the same RTDB URL. It exports `getDb()`; every other server lib and `server/index.js` obtains its handle from there. Two spots do a late dynamic import (`server/index.js:4920`, `:4040`). The init deliberately does **not** throw on failure — it logs and returns `null`, so on a machine without credentials every Firebase call silently no-ops. Server code uses namespaced syntax (`db.ref(path).once('value')`, `.set`, `.update`, `.push`, `.on('value'|'child_added'|'child_changed')`, `.child()`), and `vmPoolManager.js:209,402,490` / `vmHealthMonitor.js:321` use `db.ref().update({absolutePath: value})` for atomic cross-subtree writes.

**Paths written by both browser and server.** `competitions/{compId}/config` (and `config/virtiusSessionId`); `competitions/{compId}/currentGraphic`; `competitions/{compId}/commentary/{talentId}`; `alerts/{compId}/{alertId}` (server creates/resolves, browser acknowledges); `talentRoster/{talentId}`; `bookingTokens/{token}` (server creates, browser marks responded); `teamsDatabase/teams/{teamKey}` (browser edits, `rtnStatsService` writes `rtnId`/`league`); `teamsDatabase/headshots/{key}` (browser saves, `useCompetitions` backfills `rtnId`); `rtnCache/*` (server proxy routes and `roadToNationals.js` both write); `themes/{themeId}` (server via `PUT /api/admin/themes`, browser directly for `sponsors/{index}`). Also worth flagging as a three-way node: `competitions/{compId}/scoreBug` is written by the SPA (`ScoreBugPanel.jsx`) *and* by a browser source (`overlays/team-bug.html`), and never by the server.

**Paths the SPA can only reach through the Coordinator server (HTTP), never directly:** the whole `competitions/{compId}/obs/*` subtree, `templates/obs/*`, `competitions/{compId}/production/{cameras,settings,overrides,history,rundown}`, `config/talentComms`, and `vmPool/*` for writes (`useVMPool.js` subscribes read-only and mutates via `POST /api/admin/vm-pool/*`).

**Database rules.** There is **no** `database.rules.json`, `firebase.json`, or `.firebaserc` anywhere in the repo (verified by `find` across the tree). Rules are managed only in the Firebase console. Three places document what they are supposed to be: `DEPLOYMENT.md:138-150` (`".read": true, ".write": true`), `show-controller/src/lib/roadToNationals.js:549-555` (the `rtnCache` grant, with an explicit in-memory fallback when it is denied), and `docs/PRD-Commentary-Talent-CRM/implementation-plan.md:180-185, 651-656, 837-839` (a proposed per-path map for `talentRoster`, `bookingTokens`, `surveyResponses`). The client config in `firebase.js` and the three renderer copies are all committed in plaintext, which only works because the rules are effectively open — the public `/book/:token` and `/survey` routes depend on that.

**Orphans and mismatches found while mapping (all confirmed in code):**
- Read-only, never written in the repo: `competitions/{compId}/status`, `competitions/{compId}/compositeTeams`, `competitions/{compId}/production/talent`, `competitions/{compId}/production/equipment`, `competitions/{compId}/rundown/defaultContentSequence`, `schoolRecords/*`, `teamsDatabase/honors`, `teamsDatabase/milestones`, `scoreBug/config/flashDuration`.
